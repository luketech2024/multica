| 编号 | 目标 |

## 4. 三条最终验收路径

| 路径 | 需要观察到的结果 |
| --- | --- |
| 简单代码修改 | 继承默认运行时，选择代码库，规格及适用设计确认，计划单独确认后执行，测试交付，归档确认后完成归档 |
| 无服务器的发布任务 | 发布目标确认后可保存草稿，部署前才提示环境缺口，补齐后可从原阶段继续 |
| 上游变更引起的文档更新 | 以同步记录或提交范围创建文档任务，在 `docs_{说明}` 独立交付并合并，来源追溯完整 |

浏览器场景使用隔离工作区与受控执行器验证正常入口。实际智能体运行与真实服务器部署另按具体任务授权验证。

### 验收入口

1. 工作区设置中选择 OneSpec 默认运行时。
2. 在项目详情的 OneSpec 区域启用流程、指定总览代码库并初始化平台团队。
3. 新建任务，在任务详情 OneSpec 面板选择类型、执行阶段并分别确认产出。
4. 配置晚于任务创建时，尚未开始且无产出的任务可以更新执行配置。
5. 发布任务在发布准备阶段选择预发布或生产环境，创建草稿后进入发布中心补齐应用及机器配置。

- 发布草稿默认选中 staging，用户可以在创建前切换 prod。
- 浏览器测试使用隔离工作区与受控产出数据。实际 Cursor 模型执行、多仓库业务代码协作和真实服务器部署尚待具体项目验收。
- Git 临时仓库测试覆盖四类命名、worktree 归属、重复执行与来源不匹配拒绝。远端合并、推送和实际冲突解决需按项目授权执行。
- Web/API 已按最新代码构建并在本地启动，Windows CLI 已安装，daemon 已重启。
