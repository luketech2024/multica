## 1. 预期结果

创建工作区后，用户即可看到七类 OneSpec 内置角色。运行时尚未接入时，界面显示“待配置运行时”。工作区管理员配置可用运行时后，系统建立对应的智能体执行实例和默认团队绑定。用户明确选择 OneSpec 后，项目自动绑定本工作区对应的内置通用团队并继承默认运行时，也可选择专用运行时或自定义智能体。

平台提供统一角色定义。启用关系、执行实例、权限、运行时及任务记录分别归属工作区。

本方案复用已有角色定义、团队初始化、项目角色、运行时授权、活动记录和共享前端组件，补齐自动启用、自动绑定、状态展示与历史数据处理。

## 3. 数据模型方案

### 3.1 内置定义

继续使用 `OneSpecRoles`、`OneSpecRoleNames`、`OneSpecSystemInstructions` 和既有技能规则提供定义。角色标识继续采用 `sched`、`product`、`dev`、`test`、`ops`、`docs`、`git`。

内置指令通过既有系统指令组合机制参与执行，实例中的用户指令用于承载该工作区自己的补充配置。

### 3.2 工作区启用关系

新增 `onespec_workspace_role` 表，记录工作区的内置角色启用关系。迁移 673 建表，674 建立唯一索引，均提供对应回滚迁移。

| 拟议字段 | 用途 |
| --- | --- |
| `workspace_id` | 工作区归属 |
| `role_key` | 内置角色标识 |
| `enabled` | 启用或主动停用状态 |
| `configured_by` | 启用或修复操作的责任账号，用于追溯与后续实例归属校验 |
| `revision` | 防止过期配置覆盖新配置 |
| `created_at`、`updated_at` | 创建与变更时间 |

对 `workspace_id + role_key` 建唯一约束对应的索引。按仓库规范使用独立迁移和 `CREATE UNIQUE INDEX CONCURRENTLY`，关系校验、工作区删除清理由应用处理。

这个方案将“角色已启用”与“执行实例已准备好”分别表示。缺少运行时时，角色仍可展示，实际 agent 实例在合法运行时确定后建立。需求中的工作区实例体验由启用记录与后续执行实例共同承载。

这是本方案的实现建议。它需要在配置页面及智能体列表中合并展示待配置角色，明确与可执行实例的状态区别。

### 3.3 执行实例

继续使用现有 `agent` 表及 `system_key = onespec:<role>` 标识。按工作区、运行时、角色查找可复用实例。

- 已有活跃实例需要检查归属、所有者、授权和绑定完整性。
- 项目改用其他运行时时，查找或建立该运行时对应实例，再更新项目映射。
- 归档实例及主动停用角色需要作为用户选择处理，普通补齐操作应显示冲突或待修复状态。
- 通过工作区初始化锁和唯一启用关系实现可重复执行，迁移前需检查现有重复实例情况。
- 对已有重复实例保留历史引用，通过显式绑定选定有效实例，避免自动删除或合并有执行历史的数据。

### 3.4 项目绑定来源

在现有项目角色配置中增加可选来源标识，建议采用 `binding_source`。

| 值 | 含义 |
| --- | --- |
| `onespec_default` | 系统自动解析的 OneSpec 默认角色 |
| `explicit` | 用户明确选择或确认的绑定 |

已有 agent 或 runtime 的历史绑定缺少来源时，按显式绑定保留。用户选择 OneSpec 后，可自动补齐未设置 agent 和 runtime 的启用角色。用户在团队编辑器中调整的角色记录为 `explicit`，包括主动清空的绑定。仅凭名称或 `system_key` 无法确定用户当初是否主动选择。

项目运行时来源由现有配置表达。项目 `runtime_id` 有值时为项目覆盖，空值时继承工作区默认值。

## 4. 后端业务改动

### 4.1 提取团队业务服务

将现有 `ProvisionOneSpecTeam` 中查找实例、创建实例、设置调用权限、校验技能与保存团队的逻辑提取到可接受事务上下文的业务服务。HTTP handler 负责请求解析、身份校验、版本检查及响应。

服务分为三个职责。

1. 确保工作区角色启用关系完整。
2. 根据配置和授权解析有效运行时，准备相应执行实例。
3. 合并项目默认绑定，保留显式选择并记录活动。

内部返回结构化结果，至少区分已完成、待配置、授权不足、资源失效和可重试失败。现有可见性、运行时类型、模型及技能校验需继续通过已有逻辑完成。

### 4.2 工作区创建

工作区、owner、默认状态和角色启用关系放在同一事务内建立。角色记录创建失败时，本次创建回滚，前端保留表单并允许重试。

工作区事务提交后，若已有适用运行时，进入准备执行实例的步骤。该步骤失败可显示待修复状态，用户从工作区配置入口重试。成功响应需要明确区分工作区创建结果和团队准备结果。

这将 PRD 中的初始化失败划分为基础关系创建失败与后续执行配置失败两种情况。

### 4.3 工作区默认运行时保存

1. 检查 owner/admin 身份、工作区归属、运行时所有者授权和请求版本。
2. 准备适用的 OneSpec 实例，校验技能与调用授权。
3. 同事务保存默认配置与本次活动记录。
4. 返回有效配置、受影响项目及当前用户可执行状态。
5. 前端失效相关工作区配置、团队、项目和智能体查询缓存。

清空默认值后，自动继承项目应展示待配置状态。已显式指定运行时的项目根据自己的配置解析。

### 4.4 项目创建与配置

- 新增 OneSpec 开关，默认关闭。显式开启后自动绑定平台通用智能体，运行时默认继承工作区，也可指定项目运行时。
- 开启 OneSpec 的项目在创建事务中建立配置及默认来源标记。
- 有合法运行时时，创建或复用实例并完成默认团队绑定。
- 运行时缺失、离线等情况分别返回配置状态，允许用户先保存项目。
- 创建请求显式提交非法或越权运行时时返回校验错误，用户修改后重试。
- 保存项目覆盖配置时，只调整该项目的自动绑定，显式自定义角色展示匹配与冲突结果。
- 同一个角色的 agent 与 runtime 必须一致。

### 4.5 默认值变更与执行快照

建议采用“配置实时解析，执行时固定快照”的语义。

- 工作区默认值变更后，继承项目的有效配置立即反映新值。
- 项目 GET 接口只计算和展示有效配置。
- 在项目保存、显式补齐或首次执行准备时，事务内物化需要的默认团队引用。
- 已存在的流程快照继续按其既有配置执行，并在页面显示其实际运行时。
- 尚未产生执行记录的待配置流程，可通过显式准备动作刷新快照后启动。
- 运行时被撤销授权时继续应用既有撤销与任务取消规则，配置快照不能授予已失效权限。

该建议用于避免一个默认值保存请求同时更新大量项目。它将 PRD 中“完成待配置项目绑定”细化为有效配置立即可见、执行前确保实际引用完整。若需要保存时立刻持久化所有项目映射，应另行评估项目规模与批量任务机制。

### 4.6 绑定授权与调用授权

实施前需区分两条已有路径。

- 绑定运行时或创建 agent 时，检查执行该配置动作的用户是否获得运行时所有者授权。
- 调用已有共享 agent 时，按当前 agent 调用规则与其所有者的有效运行时授权判断。

工作区成员可以被授权使用共享智能体，直接获得机器配置权仍需要独立授权。默认配置页分别展示团队可用性和当前用户可执行性，避免把所有成员可用性简化为一个布尔值。

自动创建执行实例时，不能仅根据历史 `configured_by` 代替当前授权判断。复用实例需核验其所有者仍是工作区成员且运行时授权有效。所有者离开后的修复由具有相应权限的用户重新完成。

## 5. API 调整建议

以下为拟议增量，已有响应字段与错误语义需兼容已安装客户端。

| 接口 | 拟议改动 |
| --- | --- |
| `GET /api/workspaces/{id}/onespec` | 返回角色启用关系、有效运行时及团队准备状态；配置权限复用当前工作区成员角色 |
| `PUT /api/workspaces/{id}/onespec` | 保存默认值时准备团队，返回有效运行时及团队准备结果 |
| `POST /api/workspaces/{id}/onespec/team` | 新增工作区补齐、重试入口，要求管理权限 |
| `GET /api/projects/{id}/onespec` | 返回运行时来源、有效团队、待配置或冲突原因 |
| `PUT /api/projects/{id}/onespec` | 保存项目覆盖并准备对应默认团队 |
| `POST /api/projects/{id}/onespec/team` | 复用现有入口，增加保留显式配置的补齐语义 |
| `POST /api/projects` | `onespec_enabled` 默认关闭，显式开启后准备团队；创建后通过 OneSpec 配置接口读取准备状态 |

状态字段采用可扩展枚举，当前区分 `pending_runtime`、`needs_setup`、`ready`、`runtime_offline`、`access_denied`、`binding_invalid`、`disabled`、`archived`。角色停用与 agent 归档额外展示，错误信息过滤凭据和内部连接细节。

状态根据当前配置和资源情况计算。初始化失败返回请求错误，事务回滚，页面展示错误并提供重试。

## 6. 前端改动

### 6.1 工作区设置

- 在 OneSpec 配置区域展示七类角色及准备状态。
- 展示默认运行时和当前可用状态，缺少授权时展示相应原因。
- 提供配置、补齐、重试入口，保存后展示实际结果。
- 非管理员可查看状态，界面指明可由谁完成配置。
- 运行时名称和选择器使用仓库既有显示与分组工具。

### 6.2 新建项目与项目设置

- 新建项目提供 OneSpec 启用选项与“使用工作区默认值”。
- 展示将采用的运行时和团队，允许先保存待配置项目。
- 项目详情展示配置来源，区分自动角色与显式自定义角色。
- 项目切换运行时时展示冲突和影响范围，再提交用户选择的配置。

### 6.3 智能体列表与执行入口

- 列表展示尚未准备执行实例的内置角色，状态为待配置。
- 有多个运行时实例时按角色和运行时清楚区分。
- 待配置角色链接到可操作的配置入口。
- 用户点击开始执行时获得具体原因，支持修复后重试。
- 任务和已有流程显示实际执行快照，避免默认值更新后展示错位。

### 6.4 共享层与兼容

更新 API schema、查询键和缓存失效逻辑。组件放在共享 views 中供 Web、Desktop 使用，路由跳转通过已有导航适配器实现。新增文案覆盖共享端全部语言。

Mobile 的旧 API 调用需继续可用，新增配置界面的适配范围待实施前确认。

## 8. 数据迁移与补齐

1. 先检查当前迁移最大编号和实际数据库结构，按恢复开发时的基线生成迁移。
2. 结构迁移建立角色启用关系及约束。
3. 旧工作区通过管理入口执行可重复的业务补齐，保留既有运行时、调用权限和角色绑定。
4. 识别已有 OneSpec agent 的角色、运行时、归档状态及项目引用。
5. 为缺少启用关系的角色补齐记录，对已有实例提供复用或待修复结果。
6. 在工作区删除流程中清理启用记录。项目删除沿用项目配置清理链路并补齐新增引用。
7. 回滚迁移前需核对应用版本和新字段依赖，实施时给出可执行的回滚步骤。

## 10. 实施顺序与恢复开发检查

1. 用户已授权恢复开发，并确认新项目的 OneSpec 开关默认关闭。

## 11. 已确认的实施决策

| 决策 | 本方案建议 |
| --- | --- |
| 未绑定运行时的内置角色如何保存 | 先保存工作区启用关系，合法运行时确定后创建执行实例 |
| 新项目默认行为 | 已确认，用户明确选择 OneSpec 后自动绑定内置团队；未选择时沿用普通项目行为 |
| 默认值变更传播 | 有效配置立即更新，执行前事务内准备实例与固定快照 |
| 已有配置解释 | 历史缺少来源字段的角色按显式选择处理 |
| 执行实例所有者 | 必须选择当前合法、获运行时授权的责任账号，初始化动作记录真实操作者 |
| 运行中流程迁移 | 使用既有快照，新配置用于后续新建或显式准备的流程 |
| 移动端范围 | 保证 API 兼容，配置页面范围另行确认 |

实现遵循用户明确选择 OneSpec 后自动绑定的规则。历史非空绑定继续作为显式配置保留，初始化失败通过事务回滚和重试处理。
